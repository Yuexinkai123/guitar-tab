# 弦外 · 音乐转吉他六线谱

在本机浏览器中上传歌曲，使用 Demucs 六声部模型分离吉他，再用 Basic Pitch 神经模型识别和弦、分解和弦及重复拨弦，推算标准调弦的六线谱。也保留“人声旋律改成吉他”的单音模式。

## 启动

需要 Python 3.12。Windows 双击 `start.bat`，保持程序窗口打开，在浏览器访问 <http://127.0.0.1:8765>。

也可以手动运行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8765
```

首次安装需要下载 Python 依赖，首次提取吉他需要下载约 55 MB 的 Demucs 权重，人声模式另需约 84 MB；下载会校验哈希，缓存后可以离线运行。Basic Pitch ONNX 权重随项目附带。音频不会发送到第三方服务。无须 API Key，无须 FFmpeg。模型和临时歌曲保存在 `data/`。请预留约 2 GB 磁盘空间。

## 使用

1. 上传 MP3 / WAV / FLAC / OGG，最大 40 MB。
2. 默认选“完整歌曲 · 提取吉他声部”，分析范围默认整首歌曲，从开头处理。纯吉他录音选“纯吉他录音 · 和弦 / 指弹”。若想弹演唱旋律，选“人声旋律改成吉他”。也可手动选择 15 / 30 秒等片段。
3. 对照原曲、提取的声部与合成六线谱试听。播放器有进度、跳转、暂停续播与调速，同时高亮和弦各音。点击数字可修改音高和指法，同弦同时发声的修改会被拒绝。
4. 下载 SVG 谱图或文本谱，使用“打印 / PDF”保存 PDF。也可下载当前修改后的 MIDI（保留实测时间）或 MusicXML（估计节奏），在 MuseScore 等谱软件中继续编辑。导出前核对参考 BPM 并选择拍号，拍号默认 4/4，并非自动识别结果。

## 当前范围与限制

- 输出是**自动识别的时间六线谱草稿**。吉他模式可包含和弦与前奏，但不保证逐音复刻，也不会把没有吉他的录音自动编成完整指弹曲。人声模式仍只还原主旋律。
- 支持整首歌曲（最长 30 分钟、文件最大 40 MB），或分析 5～90 秒片段。页面提供“整首歌曲”和 15 / 30 / 60 / 90 秒。内部按 30 秒分段，带边界重叠，保留静音与原始时间，合并后统一安排指法。人声音频逐段写入磁盘，避免整首一次性推理占用大量内存。
- 网页横轴是片段相对秒数。MusicXML 会按参考 BPM 与用户指定拍号量化到节奏网格，添加小节、休止与延音。快音需要时自动细分网格。参考 BPM、节奏和起拍位置均需人工核对；没有自动识别拍号、调号或自由速度。
- 合唱、和声、混响、连续同音、气声、滑音等可能产生错音或漏音。棕色数字标记低置信度音符；这不等于其他音符保证正确。
- 标准调弦 E2 A2 D3 G3 B3 E4，使用 0～15 品。吉他模式保留原始音高，禁止同弦同时发声并限制品位跨度；无法安排的音会省略并报告。人声模式必要时整体移八度并提示。指法是算法推算，不能保证是录音中的原指法。
- 纯器乐完整混音不能通过“人声模式”可靠提取主旋律；“单旋律”模式要求录音以单音为主。
- CPU 运行时，首次分析还涉及模型加载与 JIT 编译，可能需要数分钟。没有伪造识别结果；“示例旋律”明确为手工演示。
- 完成任务保存于本地，服务重启可恢复最近 12 份后台结果。页面中的手工编辑刷新会丢失，请及时导出。后续提交任务时清理完成超过一小时的任务；退出不会自动删除磁盘文件。需清理时先关闭程序，再删除 `data/` 下 UUID 命名的任务目录；保留 `models/` 可避免重新下载。
- 默认仅监听 `127.0.0.1`，供本机使用。尚未包含账号、任务取消或公网部署所需的并发管理。失真电吉他、多把吉他叠录、密集混音及声部分离串音可能明显降低准确度。

## 验证

```powershell
.\.venv\Scripts\python.exe -m pip install pytest httpx
.\.venv\Scripts\python.exe -m pytest -q
```

测试包括合成已知音高的实际音频识别、静音与时间范围、可弹奏的指法、异步 API 错误处理与结果音频。

前端测试（仅开发时需要 Node.js）：

```powershell
npm ci
npm test
```

覆盖示例标识、音符编辑、导出的 SVG/XML 有效性、文本谱内容和窄屏谱行分段。

已另外使用 librosa 提供的带人声及伴奏示例歌曲 `Karissa Hobbs - Let's Go Fishin'` 跑通 15 秒完整处理链路（原曲 20 秒起），生成 17 个音符，并验证 HTTP 上传、任务完成和人声音频下载。这是功能验证，不是逐音准确率评测。

整首模式还通过了 96 秒合成音频的跨段音符、长静音与末尾保留测试，以及上述示例歌曲的整首 HTTP 验证：132.989 秒、5 个处理段、140 个旋律音符，导出的人声音频包含完整的 2,932,408 帧（22,050 Hz）。

新增多音识别通过了 3 组和弦的 9 个已知目标音检查，并实际处理了上述示例歌曲 20～35 秒的吉他声部。真实样曲导出的 MusicXML 通过 MusicXML 4.0 XSD 校验。这些验证不等于复杂音乐准确率测评。网站研究、实现对应及差距详见 [研究记录](docs/songscription-research.md)。
